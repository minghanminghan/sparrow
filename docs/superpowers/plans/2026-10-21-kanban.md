# Kanban (`kb`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `kb`, a local file-based kanban tracker. It has a Next.js web app (Board, All tasks, Task detail) and an agent CLI. Both share one core library over a folder of Markdown task files.

**Architecture:** This is one npm package at the repo root.
- `src/core` owns the file format, locks, atomic writes, operations, and the in-memory index. It is plain Node with no Next imports.
- `src/cli` is bundled with tsup to `dist/cli.js`, which is the `kb` bin.
- `src/app` is a Next.js App Router app. Its route handlers call `core`. A `globalThis` singleton holds the index and a chokidar watcher, and it pushes changes to the browser over SSE.

**Tech Stack:**
- App: Next.js 16, React 19, TypeScript, Tailwind v4.
- Core: `yaml`, `proper-lockfile`, `chokidar`, `fractional-indexing`.
- UI: `@dnd-kit/core` and `@dnd-kit/sortable`, `zustand`, `react-markdown` with `remark-gfm`, `rehype-sanitize` and `rehype-highlight`.
- Build and test: `tsup`, `vitest`.

**Spec:** `docs/specs/2026-10-21-kanban-design.md`. Executors read the spec and this plan together.

## Global Constraints

- **Follow `CLAUDE.md`.** Keep code simple. Write minimal comments and docs. Write unit tests only where this plan names them. Keep docblocks under 12 lines.
- **Files are the source of truth.** There is no database, and nothing derived is written to disk (spec §4).
- **Layout:** `<ws>/.kanban/config.yaml`, `<ws>/.kanban/trash/`, `<ws>/tasks/<ID>.md`, `<ws>/AGENTS.md` (spec §6.1).
- **Workspace lookup:**
  - CLI: `--dir`, then `KB_DIR`, then walk up from the current directory to the nearest `.kanban/`.
  - Web app: `KB_DIR` only.
- **IDs:** `<idPrefix>-<n>`, never reused. Deleted files in `trash/` count when picking the next ID.
- **Unparseable files:** never rewrite a file that fails to parse.
- **Timestamps:** ISO UTC (`new Date().toISOString()` with milliseconds removed). `due` is `YYYY-MM-DD`.
- **Comment header line:** exactly `### <ISO> · <author>`. The separator is a space, U+00B7, and a space.
- **CLI output:** JSON when `--json` is set or stdout is not a TTY. Errors go to stderr as `{"error":{"code","message"}}`.
- **Exit codes:** `0` ok, `1` usage, `2` not_found, `3` conflict, `4` invalid.
- **Server:** binds to `127.0.0.1`. Default port is `4600`. Everything must work under `next start`, not only `next dev`.
- **Feel targets:**
  - A drag or status change shows on screen in under 100 ms, so the UI updates before the server replies.
  - A change made outside the app shows in the open tab in under 1 s.
  - The board stays smooth with 2,000 tasks.
- **`AGENTS.md`** must be under 150 lines.

## Review Focus

1. **A hand-edited file with broken YAML or a missing `id`, `title` or `status`.**
   - Expected: it shows as invalid with the parse error, it is never rewritten, and any operation on it fails with code `invalid`.
   - Test: Task 3, `invalid file is never rewritten`.
2. **A comment whose text contains `### heading` or `## Comments` lines.**
   - Expected: the text stays inside that comment, and the body is unchanged.
   - Test: Task 2, `comment text with headings survives`.
3. **A text editor saves the file while a body edit is open in the UI.**
   - Expected: a stale `bodyHash` is rejected with `conflict`. Comment and status operations made in the meantime do not conflict.
   - Test: Task 3, `stale body hash conflicts, other ops do not`.
4. **Setting a task's parent to itself or to one of its descendants.**
   - Expected: rejected with `usage`, and the file is unchanged.
   - Test: Task 3, `parent cycle rejected`.
5. **The temp files from atomic writes appearing in `tasks/`.**
   - Expected: the index and the watcher ignore them, so they never become a task or a flicker.
   - Test: Task 4, `index ignores temp files and computes backlinks`.

```ts
// workspace.ts
export function findWorkspace(opts?: { dir?: string; cwd?: string }): string  // throws KbError('not_found')
export function initWorkspace(dir: string, prefix?: string): void  // config, trash/, tasks/, AGENTS.md (template from Task 5)
export function taskPath(ws: string, id: string): string
export function readTask(ws: string, id: string): { task: Task; text: string }  // not_found / invalid
// write.ts
export async function withLock<T>(file: string, fn: () => Promise<T> | T): Promise<T>  // proper-lockfile, retries ~50 x 20ms
export function atomicWrite(file: string, text: string): void  // writes `.<name>.tmp-<rand>` in same dir, fsync, rename
// ops.ts
export type Op =
  | { type: 'setStatus'; status: string }
  | { type: 'setRank'; rank: string }
  | { type: 'setDue'; due: string | null }
  | { type: 'setAssignee'; assignee: string | null }
  | { type: 'setParent'; parent: string | null }
  | { type: 'setTitle'; title: string; baseHash?: string }
  | { type: 'setBody'; body: string; baseHash?: string }
  | { type: 'addLink'; link: Link } | { type: 'removeLink'; link: Link }
  | { type: 'addRef'; ref: Ref } | { type: 'removeRef'; url: string }
  | { type: 'addComment'; author: string; body: string }
  | { type: 'claim'; assignee: string }
export type CreateInput = { title: string; status?: string; parent?: string; due?: string; assignee?: string; body?: string; rank?: string }
export async function createTask(ws: string, input: CreateInput): Promise<Task>
export async function applyOp(ws: string, id: string, op: Op): Promise<Task>
export async function deleteTask(ws: string, id: string): Promise<void>  // moves file to .kanban/trash/
```

**Rules for `applyOp`.** It runs under `withLock(taskPath)`. It re-reads the file, applies the op, sets `updated`, and calls `atomicWrite`.
- **`setStatus`:**
  - The status must be a column key, otherwise `usage`.
  - Set `completed` when the task enters a done column. Clear it when the task leaves one.
- **`setTitle` and `setBody`:** if `baseHash` is given and does not equal `hash(current field)`, fail with `conflict`.
- **`setParent`:**
  - The parent must exist, otherwise `not_found`.
  - Walk up the parent chain. If the chain reaches `id`, fail with `usage`.
- **`claim`:**
  - If the task has an assignee other than the claimer, fail with `conflict`.
  - Otherwise set the assignee and set the status to the `active` column, through the same `completed` logic as `setStatus`.
- **`addLink`:**
  - Linking a task to itself fails with `usage`.
  - Adding a link that already exists changes nothing.
- **`addRef`:** adding a URL that already exists changes nothing.

**Rules for `createTask`.**
- It runs under `withLock('.kanban/config.yaml')`.
- To pick the next ID, scan `tasks/` and `trash/` for the highest `n`, then add 1.
- Write the file with flag `wx`.
- Defaults:
  - `status`: the `ready` column.
  - `rank`: `generateKeyBetween(<last rank in that status>, null)`.

### Task 6: Server: API, index singleton, watcher, SSE

**Files:**
- Create: `src/server/state.ts`, `src/app/api/tasks/route.ts`, `src/app/api/tasks/[id]/route.ts`, `src/app/api/events/route.ts`

**Interfaces:**
- Consumes: the core barrel.
- Produces:
```ts
// state.ts — singleton on globalThis.__kb so dev hot-reload never creates a second watcher
export function getState(): { ws: string; index: Index; emitter: EventEmitter }  // throws if KB_DIR unset
export type ServerEvent = { type: 'upsert'; task: TaskView } | { type: 'remove'; id: string } | { type: 'snapshot'; index: Index }
```
- **HTTP:** every route sets `runtime = 'nodejs'` and `dynamic = 'force-dynamic'`.

  | Route | Body | Returns |
  |---|---|---|
  | `GET /api/tasks` | | `Index` |
  | `POST /api/tasks` | `CreateInput` | `TaskView` |
  | `POST /api/tasks/[id]` | `{ op: Op }` | `TaskView` |
  | `DELETE /api/tasks/[id]` | | `{ ok: true }` |
  | `GET /api/events` | | SSE stream; sends `snapshot` first, then live events |

  `KbError` maps to an HTTP status: `usage` 400, `not_found` 404, `conflict` 409, `invalid` 422. The response body is `{ error: { code, message } }`.

- **Watcher:**
  - Use chokidar on `<ws>/tasks` with `ignoreInitial: true`, ignoring every name where `!isTaskFile(name)`.
  - Debounce for 50 ms.
  - On any change, rebuild the index and emit `upsert` (or `remove`) for every task whose view changed.
  - Compare views by `JSON.stringify` of the `TaskView`, because backlinks and progress on other tasks can change too.
  - Successful API writes also rebuild and emit at once, so the client does not wait for the watcher.
