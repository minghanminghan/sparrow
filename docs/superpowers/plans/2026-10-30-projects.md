# Projects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tasks belong to projects with short keys; every visible task id becomes `KEY-N`, numbered per project, with project colors, a multi-select project filter, and project pages.

**Architecture:** The SQLite integer `tasks.id` stays the real primary key and never leaves `src/core/store.ts` / `src/core/attachments.ts`. Those two files translate between the integer and the key; above them (`ops`, `indexer`, API, SSE, client store, CLI) `Task.id` is the key string `SPAR-28`, so most code keeps working unchanged. A new `projects` table holds key, name, color, and the next number. `Index` gains `projects`.

**Tech Stack:** Next.js 16 app router, React 19, zustand 5, Tailwind v4, vitest, `node:sqlite`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-30-projects-design.md`

## Global Constraints

- Project key: a letter first, then letters or digits, 1–6 characters total. Stored and shown uppercase. Input is case-insensitive everywhere (`spar-1` = `SPAR-1`).
- Task key format: `<PROJECT>-<N>`, `N` a positive integer, per-project counter.
- Bare numbers (`28`) are rejected as task ids everywhere with a `usage` error that says to use a key like `SPAR-28`.
- No default project. A create needs a project, or a parent (it then inherits the parent's project).
- No `--color` CLI flag. Colors come from one fixed palette (`PROJECT_COLORS`), readable as text on white.
- Keys never change; tasks never move between projects; projects are never deleted.
- Existing tasks: project `SPAR` (name "Sparrow"), same numbers; next `SPAR` task is `max(existing id) + 1` (`SPAR-32` on prod today).
- URLs: task page `/t/SPAR-28`, projects list `/p`, project page `/p/NEWS`.
- Breaking change for the API and CLI: the PR title must be `feat!: ...` so semantic-release bumps the major version and old CLIs fail with exit code 5.
- Conventional commits per task; reuse the existing gray Tailwind look.

## Review Focus

1. Prod DB after migration: parents, links, attachments, comments, and `[[N]]` mentions all still point at the same tasks, and the next `SPAR` create is `SPAR-<max id + 1>` (Task 2 test `migration 5 keeps numbers and rewrites mentions`).
2. Mixed case and bare numbers in the CLI and URLs (`sparrow show spar-1`, `sparrow show 28`, `/t/spar-28`) → the first works, the second fails with the "use a key like SPAR-28" message (Task 1 tests; Task 4 test `GET /api/tasks/spar-1 returns SPAR-1`).
3. Subtask made in a different project from its parent, by create or by `setParent` → `usage` error, nothing saved (Task 2 test `subtask project must match parent`).
4. A color or name change made on the project page shows on another open board without reload (Task 3 test `refresh emits a snapshot when a project changes`).
5. A create queued in the phone outbox before the upgrade (no project, numeric parent) → the server rejects it and the pending card shows the error with Retry/Discard; it is never silently dropped (Task 7 verification step).

  - `normalizeProjectKey(s: string): string` — trims, uppercases, validates; throws `KbError('usage', 'invalid project key "<s>": use 1-6 letters or digits, starting with a letter')`.
  - `normalizeTaskKey(s: string): string` — uppercases and validates `^[A-Z][A-Z0-9]{0,5}-[1-9]\d*$`. A bare number throws `KbError('usage', 'task ids are keys now, like SPAR-28 (got "<s>")')`; anything else invalid throws `KbError('usage', 'invalid task id "<s>"')`.

  - `MENTION_RE = /\[\[([A-Za-z][A-Za-z0-9]{0,5}-\d+)\]\]/g`
  - `PROJECT_COLORS: string[]` — 12 hex colors at Tailwind 600/700 strength (e.g. `#2563eb`, `#dc2626`, `#15803d`, `#7c3aed`, `#ea580c`, `#0f766e`, `#db2777`, `#b45309`, `#4f46e5`, `#0369a1`, `#a21caf`, `#475569`). `SPAR` uses `#2563eb`.
  - `pickColor(used: string[]): string` — random color not in `used`; random from all when every color is used.

**Interfaces:**
- Consumes: Task 1 helpers.
- Produces:
  - Migration 5 (a function): creates `projects (key TEXT PRIMARY KEY, name TEXT NOT NULL, color TEXT NOT NULL, next_number INTEGER NOT NULL)`; inserts `('SPAR', 'Sparrow', '#2563eb', COALESCE(MAX(tasks.id), 0) + 1)`; adds `tasks.project TEXT NOT NULL DEFAULT 'SPAR'` and `tasks.number INTEGER`; sets `number = id`; `CREATE UNIQUE INDEX tasks_project_number ON tasks (project, number)`; rewrites `[[N]]` → `[[SPAR-N]]` in every `tasks.body` and `comments.body` (regex `/\[\[(\d+)\]\]/g`). No `REFERENCES` on the new column (SQLite forbids it with a non-null default while foreign keys are on).
  - `loadTasks(db, key?: string): Task[]` — `id`, `parent`, and link targets are keys; `project` is set. Builds one integer→key map from all task rows (deleted included) so links to deleted tasks still resolve.
  - `saveTask(db, task: Task): string` — `task.id` must already be a key; updates the row for `(project, number)` or inserts it. Translates `parent` and link targets to integers. Returns the key.
  - `rowIdOf(db, key: string): number` — throws `not_found` if no row.
  - `readTask(db, id)` normalizes with `normalizeTaskKey` (replaces `ID_RE`).
  - `CreateInput.project?: string`. `createTask` rules, in order: normalize `project`/`parent`; if a parent is given its project is used, and a different `project` throws `usage` (`"<child project> task cannot have parent <parent key> from another project"`); if neither is given throw `usage` `a project is required (one of: <keys, comma-separated>)`; unknown project throws `not_found`. Number from `UPDATE projects SET next_number = next_number + 1 WHERE key = ? RETURNING next_number - 1`. The `clientId` replay path is unchanged.
  - `apply` normalizes ids in `setParent`, `addLink`, `removeLink`; `setParent` to a task in another project throws `usage`.
  - `deleteTask`, attachment functions take keys and use `rowIdOf` internally. `loadAttachments` returns a map keyed by task key.
  - `indexer.ts` uses `MENTION_RE` from `keys.ts` and uppercases matches.
